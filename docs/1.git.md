# git 分支开发管理流程
- 从 dev 分支创建 feature 分支, 在 feature 分支上开发新功能, 开发完成后，合并到 dev 分支.
- 从 dev 分支创建 hotfix 分支, 在 hotfix 分支上修复 bug, 修复完成后，合并到个人所属的 dev 分支.
- 管理员 review 成员所属 dev 分支并合并至 main 分支.

# git 命令
- stage(add) 是“往暂存区放”，stash 是“把改动整包拎走留空桌子”。
  - stage(add) stage 与 add 互为 alias
  - stash 临时“擦桌子”——把改动先封存，工作区变干净. 
    - git stash 默认会把所有工作区和暂存区的改动一次性打包；如果只想 stash 某几个文件（或某几个路径），可以用 pathspec 语法：
      - git stash push -m "partial" -- a.js b.js
    - git stash 永远以「路径」为最小单位，一旦包含某个路径，就会把该路径在“工作区+暂存区”的全部改动一起打包。
    - 默认把暂存区清空；加 --keep-index 可保留.
    - 随时 git stash apply/pop 把改动拿回来, 两者的区别是前者不删除 stash 记录, 可再次 apply；后者删除，stash 列表里消失.
  - 删除一个 stash:
    - git stash list 查看 stash 列表
      - git stash drop stash@{0} 删除第一个 stash
      - git stash clear 删除所有 stash
- 查看 git 仓库 Staged Changes 状态:
  - 命令: git status, -v 可以查看文件详细内容.
- 创建并切换到新分支
  - 新命令：git switch -c <分支名>, 旧命令：git checkout -b <分支名>
- 从指定起点创建分支 (从 main, 某个 tag 或某次提交)
  - 命令: git branch <分支名> <起点>
  - 示例:
    - git branch feature/search main
    - git branch fix/login v1.0.0
    - git branch hotfix/timeout a1b2c3d
- 将新分支推到远程并建立追踪（相当于“创建远程分支”）
  - 命令: git push -u origin <分支名>
  - 示例: git push -u origin feature/search
- 查看分支
  - 本地分支: git branch, 全部分支(包含远程): git branch -a, 仅远程分支: git branch -r
- 删除分支
  - 命令: git branch -d <分支名>, 强制删除: git branch -D <分支名>

# 基本项目开发流程
- 从 dev 分支创建 feature 分支: `git switch -c feature/feature-name dev`
- 在 feature 分支上开发新功能, 开发完成后，合并到 dev 分支: `git switch dev && git merge feature/feature-name`
- 从 dev 分支创建 hotfix 分支: `git switch -c hotfix/bug-name dev`
- 在 hotfix 分支上修复 bug, 修复完成后，合并到个人所属的 dev 分支: `git switch dev/zzx58 && git merge hotfix/bug-name`
- 管理员 review 成员所属 dev 分支并合并至 main 分支: `git switch main && git merge dev/zzx58`

# 相关问答
- merge 和 pull 的区别:
  - merge: 将一个分支的更改合并到当前分支. 可以手动解决冲突.
  - pull: 从远程仓库获取最新更改并合并到当前分支. 相当于 `git fetch && git merge`
